## 2. What we use (in order)

**Tier 1 - own procedural art (default, no licence risk, v1).**
Written by us, committed as code:
* `scripts/gen_office2_tiles.mjs` draws `app/public/office2/tiles.png` (a 16 x 8 grid of 32 px tiles = 512 x 256) with a real tile set: 3 floor types x 2 tones (wood, carpet, tile), brick/plaster walls with top-edge shading, doors, desks with monitors (2 variants), chairs, meeting table sections, whiteboard, bookshelf, server racks, machines, sofas, vending machine, plants (3), rugs, windows, wall posters, ceiling-light pools. Shading rules: 1 px dark outline on the lower/right edge, 1 px light on the upper/left edge, 3-colour ramp per material, no gradients.
* `app/src/office2/avatarArt.ts` draws the avatar layers procedurally at 32 x 32 with the same 3-colour ramp rule.
The generators are deterministic: same script -> byte-identical PNG (the test compares a hash).

**Tier 2 - founder-supplied CC0 pack (optional upgrade, later).**
If the founder wants nicer art without writing it: download a **CC0** pack by hand (examples to check: Kenney "Tiny Town"/"Roguelike Characters"/"Modern Interiors"-type packs; the founder must read the licence page on the day of download and keep a copy of it) into `app/public/office2/vendor/<pack>/` together with `LICENSE.txt` and a `manifest.json` that maps pack files to our slots (`floor`, `wall`, `desk`, ..., avatar `body/hair/outfit`). A later prompt (P-optional-A) adds the manifest loader. Nemotron never downloads art.

**Tier 3 - generated art (optional).** Image generators or tools like PixelLab are allowed only if the tool's terms grant commercial use of outputs; save the terms as `app/public/office2/vendor/<name>/TERMS.txt`. Not used in v1.

## 3. File layout

```
app/public/office2/
  map.json                 Tiled JSON, generated by scripts/gen_office2_map.mjs
  tiles.png                generated by scripts/gen_office2_tiles.mjs (512x256, 32 px tiles)
  vendor/                  (empty until Tier 2) <pack>/{LICENSE.txt, manifest.json, *.png}
app/src/office2/avatarArt.ts   layer drawing code (Tier 1)
docs/virtualOffice/ATTRIBUTIONS.md   one line per third-party asset (empty in v1)
```

Tile index plan (so map generator and tileset generator agree; the generator script exports `TILE` constants used by both, in `scripts/office2_tiles.mjs`, imported by both scripts):

| range | content |
|---|---|
| 1-15 | floors (wood a/b, carpet blue/purple/green, tile light/dark, stone) |
| 16-31 | walls, wall tops, doors, windows |
| 32-63 | furniture (desks, chairs, tables, shelves, machines, racks, sofas, vending, plants, whiteboards) |
| 64-95 | decor (rugs, posters, floor signs, paper, cables) |
| 96-127 | overlay (tops of tall objects) |

## 4. Avatar layer spec (for `avatarArt.ts`)

* Canvas per layer: 96 x 128, frame grid 3 x 4 of 32 px; row order down, left, right, up; column order stand-left-foot, neutral, stand-right-foot (walk cycle `[0,1,2,1]`).
* Character body height 26 px inside the 32 px frame, feet baseline at y = 29, 2 px empty top margin.
* Palette ramps (shadow, base, highlight) per material; skin: 5 tones; hair colours: 6; outfit colour = `CREW_COLOR[crew]` with derived ramp; accessories: glasses, headset, cap, badge, none.
* Direction rule: left row = right row mirrored except accessories drawn per row (so a headset is on the correct side).

## 5. Attribution

`docs/virtualOffice/ATTRIBUTIONS.md` must list every non-original asset (name, author, licence, URL, date checked). Tier 1 has none. The reviewer rejects a prompt result that adds image files without an entry.
